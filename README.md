# ربات مدیریت مود روبیکا — نسخهٔ نهایی

## ⚠️ کل ریپو رو با این جایگزین کنید (فایل قدیمی نگه ندارید)

## مهم‌ترین رفع‌باگ این نسخه
**تریگر خودکار داخلی گیت‌هاب (`schedule`) حذف شد.** شما هم زنگ‌زن بیرونی
(cron-job.org) داشتید هم این‌یکی فعال بود — این دوتا با هم قاطی می‌شدن،
باعث اجراهای هم‌زمان/پیاپی می‌شدن و state.json درست ذخیره نمی‌موند (برای
همین پیام‌های تکراری می‌اومد و آمار صفر می‌موند). از الان **فقط**
cron-job.org ربات رو صدا می‌زنه.

علاوه بر این، یک «دفترچهٔ ارسال» سبک هم اضافه شد: هر پیام دوره‌ای
(مثل پیام راه‌اندازی) قبل از ارسال چک می‌کنه که در ۸ دقیقهٔ اخیر
فرستاده نشده باشه؛ ورودی‌های قدیمی‌تر از ۱ ساعت خودکار پاک می‌شن —
یعنی حتی اگه یه روز دوباره تداخلی پیش بیاد، دیگه سیل پیام نمی‌شه.

## فرمت جدید و دقیق پست‌گذاری در کانال منبع

**پیام ۱ — عکس مود (هر خط جدا، بدون برچسب):**
```
عنوان مود
توضیحات مود
ورژن
#مود #1
```
تگ `#مود` اجباریه (وگرنه عکس نادیده گرفته می‌شه — این باعث می‌شه هیچ‌وقت
عکس اشتباهی به‌جای مود اشتباه گرفته نشه). عدد بعد از `#` (اینجا `1`)
شمارهٔ یکتای این مود برای دریافته.

**پیام ۲ — بلافاصله بعدش، خودِ فایل مود:** کپشنش مهم نیست، هر چیزی
باشه یا خالی باشه مشکلی نداره؛ فایل به همون شمارهٔ عکس قبلی وصل می‌شه.

**ویدیو (یک پیام):**
```
عنوان ویدیو
#ویدئو
```

## دو حالت تحویل فایل (per-channel)
توی `config.json`، هر کانال یک فیلد `"send_file_directly"` داره:
- `false` (پیش‌فرض): فقط عکس+توضیحات پست می‌شه؛ کاربر باید `#شماره` یا
  `/شماره` رو به پیوی ربات بفرسته تا فایل رو بگیره.
- `true`: بلافاصله بعد از عکس، خودِ فایل هم مستقیم در همون کانال پست
  می‌شه (بدون نیاز به مراجعه به ربات).

## پست فوری («دکمه»)
به‌جای دکمهٔ داخل چت (که مطمئن نبود)، از خودِ گیت‌هاب استفاده می‌کنیم:
تب **Actions → Rubika Mod Bot → Run workflow**. یک فیلد به اسم
**force_post_channel** می‌بینید — عدد کانال (طبق ترتیبش در
`destination_channels`) یا کلمهٔ `all` رو بنویسید و اجرا کنید؛ همون
لحظه یک مود پست می‌شه، بدون توجه به ساعت برنامه.

## پنل مدیریت و پخش همگانی (بدون تغییر نسبت به قبل)
- کلمهٔ `پنل` (یا هرچی در `panel_keyword` گذاشتید) → لیست کانال‌ها
- عدد کانال → جزئیاتش (تعداد پست، تاریخ فعال‌سازی، روش تحویل فایل)
- رمز دلخواهتون در `broadcast_secret` → «پیامتو بفرست» → پیام بعدی برای
  همهٔ کاربرها (به‌جز کانال‌ها) ارسال می‌شه

## راه‌اندازی
1. `config.json`: `owner_guid` (با `/myid`)، `broadcast_secret` (رمز
   شخصی)، و برای هر کانال مقصد: `guid`، `name`، `channel_link`،
   `send_file_directly`.
2. زیرساخت قبلی (GitHub Secret، cron-job.org) دست‌نخورده — فقط مطمئن
   بشید cron-job.org هنوز هر ۱۰ دقیقه `workflow_dispatch` می‌زنه.
3. یک پست تستی با فرمت جدید بذارید، صبر کنید (یا دستی Run workflow)،
   بعد `#1` رو به پیوی بفرستید.

## عیب‌یابی
تب Actions → آخرین اجرا → «Run bot» → دنبال خط‌های `DEBUG:` بگردید.
حالا دو خط کلیدی جدید هم هست: `DEBUG: وضعیت لود شده` (چی از state.json
خونده شده) و `DEBUG: وضعیت قبل از ذخیره` (چی قراره ذخیره بشه) — اگه این
دوتا بین اجراها با هم نمی‌خونن (یعنی چیزی که ذخیره شد، دفعهٔ بعد لود
نشد)، مشکل هنوز سر ذخیره‌سازی گیت‌هابه و باید لاگ مرحلهٔ «Save updated
state.json» رو ببینیم.
