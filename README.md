# ربات مدیریت مود روبیکا — نسخهٔ کامل

## 🩹 این دور: رفع دو باگ ریشه‌ای + ۵ قابلیت جدید

**۱. باگ «می‌گه فرستاد ولی توی کانال نیست» — رفع شد.**
`send_file` قبلاً هر پاسخ روبیکا (حتی بدون `message_id` واقعی) رو موفقیت
حساب می‌کرد. الان با ۳ لایه کار می‌کنه: مستقیم → اگه `message_id`
نداشت یا خطا داد، دانلود+آپلود مجدد فایل → اگه بازم شکست خورد، مستقیم از
کانال منبع **فوروارد** می‌کنه (تحویل تضمین‌شده‌تر، فقط متن سفارشی از
دست می‌ره). اگه بازم شکست خورد، حالا در `/bugs` می‌بینیش، نه سکوت.

**۲. باگ «تکرار پیام‌ها» (ریشه‌ای، مثل نسخه‌ی قبلی‌تون) — رفع شد.**
وقتی روبیکا `next_offset_id` خالی برمی‌گردوند (چون صفحهٔ آخر بود)،
`last_offset_id` هیچ‌وقت جلو نمی‌رفت و همون پیام‌های قدیمی هر اجرا
دوباره پردازش می‌شدن. الان در این حالت از شناسهٔ خودِ آخرین پیام
به‌عنوان offset بعدی استفاده می‌شه (در هر ۳ جایی که این الگو تکرار شده
بود: حلقهٔ اصلی، `/update`، و پاک‌سازی انبار).

**۳. جلوگیری از ارسال تکراری:** اگه یک کاربر همون شماره رو ظرف ۱۰ دقیقه
چند بار بفرسته، فقط بار اول واقعاً فایل ارسال می‌شه؛ بقیه بی‌صدا رد
می‌شن (بدون باگ اضافه، بدون پیام تکراری).

**۴. تشخیص اسپم:** اگه یک نفر بیش از ۱۵ پیام/کامند در ۵ دقیقه بفرسته،
یک گزارش به پیوی خودت می‌ره — شامل **GUID دقیق همون فرد** (هر ۳۰ دقیقه
حداکثر یک‌بار برای همون فرد، که خودت هم سیل نشی).

**۵. تیکت‌ها:** از قبل هم GUID فرستنده رو می‌فرستاد (خط «از: ...») — فقط
واضح‌ترش کردم («GUID فرستنده: ...»).

**۶. پلن‌های زمان‌بندی + بازهٔ کاری ۹ صبح تا ۱۱ شب:** در `config.json`
بخش `schedule` سه پلن آماده‌ست (۰ = هر ۲ ساعت مود/هر ۴٫۵ ساعت ویدیو،
۱ = هر ۱ ساعت/هر ۳ ساعت، ۲ = هر نیم‌ساعت/هر ۲ ساعت)، و هر کانال مقصد با
`"plan": 0` یا `1` یا `2` انتخاب می‌کنه، یا با `mod_interval_hours` /
`video_interval_hours` اختصاصی override می‌کنه. یک `schedule: cron` هر
۱۵ دقیقه هم به ورک‌فلو اضافه شد تا حتی بدون زنگ‌زن بیرونی (cron-job.org)
هم خودش کار کنه.

**۷. عضویت اجباری — ⚠️ با یک محدودیت واقعیِ پلتفرم که باید بدونی:**
سند رسمی متدهایی که خودت فرستادی رو کامل خوندم — روبیکا **هیچ متد
رسمی مستندی برای چک عضویت یک کاربر خاص در یک کانال نداره** (برخلاف
تلگرام که `getChatMember` داره). با این حال، چون متدهای `banChatMember`/
`unbanChatMember` دقیقاً با `chat_id`+`user_id` کار می‌کنن، به نظرم
منطقیه که یک متد خواهر برای «خوندن» وضعیت هم وجود داشته باشه، فقط در
این سند نیومده. بر همون الگو، `getChatMember` رو با `chat_id`+`user_id`
پیاده‌سازی کردم:
- اگه واقعاً وجود داشته باشه و جواب بده → عضویت واقعاً و دقیق چک می‌شه.
- اگه روبیکا بگه این متد وجود نداره → به‌جای گیر انداختن همهٔ کاربرهای
  واقعی پشت یه چکِ خراب، **fail-open** می‌کنه (رد می‌شن) و یک هشدار در
  `/bugs` ثبت می‌شه که بدونی باید دستی چک کنی.
**بعد از اولین تست /start، لاگ Actions رو باز کن و دنبال خط
`DEBUG: getChatMember خام:` بگرد و برام بفرست — دقیقاً همون الگویی که
دفعهٔ قبل با ساختار پیام‌ها جواب داد.**

**تنظیمات لازم قبل از تست:**
- `config.json` → `required_join_channels`: برای هر کانال اجباری،
  `guid` (با فوروارد یه پیام از اون کانال به بات، یا /myid داخل خودِ
  کانال) و `link` رو پر کن.
- بات باید **ادمین** همون کانال‌های اجباری هم باشه (نه فقط کانال‌های
  مقصد و منبع).

## ⚠️ فقط این‌ها رو جایگزین کنید (نه state.json!)
`bot_core.py`, `run_bot.py`, و در صورت نیاز `config.json`. **هرگز state.json
رو از این پکیج جایگزین نکنید** اگه قبلاً روی ریپوتون داده‌های واقعی (مود،
کاربر، ...) جمع شده — فیلدهای جدید خودشون در کد با مقدار پیش‌فرض ساخته
می‌شن، نیازی به جایگزینی state.json نیست.

## رفع باگ اصلی این نسخه
تشخیص «عکس مود» دیگه به رشتهٔ دقیق `file_type == "Image"` وابسته نیست
(چون معلوم شد این فرض همیشه درست نبود) — حالا **بر اساس تگ متن** (`#مود`)
تشخیص داده می‌شه، دقیقاً مثل فایل. این باگی که عکس‌ها ثبت نمی‌شدن رو رفع می‌کنه.

## قابلیت‌های جدید

### ۱. دکمهٔ ثابت `/help` و `/ticket`
هم برای کاربرهای جدید، هم برای خودِ مالک (بار اولی که پیام بده)، خودکار
یه کیبورد ثابت با دو دکمهٔ `/help` و `/ticket` پایین صفحه ظاهر می‌شه.

### ۲. سیستم تیکت
هر کاربری (نه فقط مالک) می‌تونه `/ticket` بفرسته → ربات می‌گه متنتو
بنویس → بعد از نوشتن، متن تیکت (با آیدی فرستنده و زمان) به پیوی شما
می‌رسه، و به کاربر «تیکت شما ارسال شد» گفته می‌شه.

### ۳. مسدودسازی کاربران (فقط مالک)
```
/block <chat_id> <تعداد روز یا permanent> <دلیل>
مثال: /block u0Iabc123 7 اسپم می‌فرسته
مثال دائمی: /block u0Iabc123 permanent مزاحمت

/unblock <chat_id>
/blocked   -> لیست کامل مسدودها با تاریخ شروع/پایان
```
کاربر مسدود، هر پیامی بفرسته فقط دلیل و تاریخ مسدودیتش رو می‌بینه؛ بعد
از پایان مهلت، خودکار آزاد می‌شه.

### ۴. پخش پیام در همهٔ کانال‌ها (نه کاربرها)
```
/channelcast
```
می‌گه پیامتو بفرست؛ پیام بعدی رو مستقیم در همهٔ کانال‌های **فعال** پست
می‌کنه. (این جدا از رمز پخش‌همگانیِ قبلی‌ه که برای *کاربرها*ست، نه کانال‌ها.)

### ۵. پست فوری، جدا برای مود و ویدیو
```
/postmod <شماره کانال یا all>     مثلاً: /postmod all یا /postmod 2
/postvideo <شماره کانال یا all>   مثلاً: /postvideo all یا /postvideo 1
```
بدون توجه به ساعت برنامه، همون لحظه پست می‌کنه.

### ۶. عضویت اجباری در کانال — با یه محدودیت صادقانه
مستندات رسمی روبیکا **هیچ متدی برای چک‌کردن عضویت کاربر در کانال نداره**؛
پس نمی‌تونم یه قابلیت واقعی و قابل‌اعتماد براش بسازم بدون این‌که دروغ
بگم کار می‌کنه. اگه دوست دارید، می‌تونم یه نسخهٔ «افتخاری» بسازم (نمایش
لینک‌های کانال‌ها + دکمهٔ «عضو شدم» که فقط حرف کاربر رو باور می‌کنه، نه
چک واقعی) — بگید تا اضافه‌ش کنم.

### حذف‌شده: `/newguid`
چون کار نمی‌کرد (به فیلد نامستندی وابسته بود)، کامل حذفش کردم. برای
گرفتن GUID هر چتی، همیشه مطمئن‌ترین راه همینه: مستقیم داخل همون چت/کانال
بنویسید `/myid`.

## کجا چی رو عوض کنم

| برای تغییر... | برو به... |
|---|---|
| متن راهنما (`/help`) | `config.json` → `help_text` |
| متن‌های تیکت | `config.json` → `texts.ticket_prompt` و `texts.ticket_sent` |
| کلمهٔ رمز پنل | `config.json` → `panel_keyword` |
| رمز پخش‌همگانیِ کاربرها | `config.json` → `broadcast_secret` |
| خودِ کلمات دستورها (`/help`, `/ticket`, `/block`, ...) | داخل `run_bot.py` — هرجا `text == "/xxx"` یا `text.startswith("/xxx")` نوشته شده |
| کپشن مود/ویدیو در کانال مقصد | `config.json` → هر کانال → `mod_photo_extra_text`, `mod_file_caption`, `video_extra_text` |
