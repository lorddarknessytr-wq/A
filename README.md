# ربات مدیریت مود روبیکا — نسخهٔ نهایی

## 🩹 این دور

**۱. پسوند فایل (چون روبیکا اصلاً پسوند رو نمی‌فرسته):**
حالا می‌تونی زیر عکسِ مود (یا زیر خودِ فایل)، یک خط اضافه بنویسی:
```
پسوند: mcaddon
```
(یا `فرمت:` / `ext:` / `extension:`). ربات این خط رو از توضیحاتی که
عمومی پست می‌شه **حذف می‌کنه** (کسی نمی‌بینتش)، فقط برای خودش نگه
می‌داره تا وقتی فایل رو می‌فرسته، اسمش رو دقیق `<شماره>.mcaddon`
بسازه. اگه این خط رو ننویسی، ربات مثل قبل سعی می‌کنه پسوند رو از
اطلاعات خودِ فایل حدس بزنه (که دیدیم معمولاً روبیکا نمی‌ده).

**۲. `/start` بازطراحی شد:** حالا خوش‌آمد + توضیح ساده («شماره رو بفرست،
بعد /file بزن») + یادآوری `/ticket` رو با هم نشون می‌ده (بعدش، اگه
کانال اجباری تنظیم کرده باشی، لیستشون هم زیرش میاد). متنش رو با کلید
`start_text` در `config.json` می‌تونی کامل عوض کنی.

**۳. دستور `/reply` — پاسخ به تیکت:** وقتی یکی `/ticket` می‌زنه، پیامش
با GUID خودش برات میاد. حالا کافیه بفرستی:
```
/reply <همون GUID> متن پاسخت
```
و ربات دقیقاً همون متن رو مستقیم برای همون فرد می‌فرسته.

**۴. راهنمای عوض کردن ایموجی‌ها:** خودت مستقیم توی فایل‌ها ویرایش کن؛
مهم‌ترین‌هاش (متنی که زیر مودها/ویدیوها توی کانال عمومی دیده می‌شه):

| فایل | تابع | خط تقریبی | چی هست |
|---|---|---|---|
| `bot_core.py` | `send_mod` | ~434-442 | 📝 توضیحات، 🔢 ورژن، 📥 راهنمای دریافت، 🔗 لینک کانال |
| `bot_core.py` | `send_video` | ~406-414 | (فعلاً بدون ایموجی؛ خودت هر جا خواستی اضافه کن) |
| `bot_core.py` | `build_join_prompt` | ~803-814 | 📢 عضویت، 📥 راهنمای `/file` |
| `run_bot.py` | `handle_start_command` | ~127 | 👋 خوش‌آمد، 🎫 تیکت |
| `run_bot.py` | `handle_owner_message` (وضعیت کلی) | ~392-397 | ✅🕰👥🎮🎬🐞 |

بقیه‌ی ایموجی‌ها (🚫⛔🔄🧹🚨📣📡...) فقط توی پیام‌های خودِ تو (مالک) و
تیکت/گزارش‌ها هستن، عمومی نیستن — عوض کردنشون فقط ظاهریه، جایی رو خراب
نمی‌کنه. کافیه همون ایموجی رو با یکی دیگه جایگزین کنی، بقیهٔ متن دست
نخوره.

## 🩹 این دور (آخرین بروزرسانی)

**۱. توضیح باگی که در `/bugs` دیدی:**
```
ارسال فایل شکست خورد؛ مستقیم، forward و re-upload ناموفق بودند:
Server Error: 502 Bad Gateway for url: .../requestSendFile
```
یعنی هر ۳ روش ارسال (مستقیم، فوروارد از کانال منبع، آپلود مجدد) امتحان
شدن، و روش سوم دقیقاً وقتی به سرور روبیکا برای گرفتن آدرس آپلود
(`requestSendFile`) وصل شده، **خودِ سرور روبیکا** لحظه‌ای در دسترس نبوده
(502 = خطای سرور، نه اشکال کد ما). قبلاً یک 502 موقت بلافاصله کل عملیات
رو شکست‌خورده حساب می‌کرد. الان `api_call` هر خطای موقت سرور
(502/503/504) رو تا ۳ بار با فاصله دوباره امتحان می‌کنه — این نوع خطاها
دیگه به‌ندرت باعث شکست کامل می‌شن.

**۲. فرمت عجیب فایل مود موقع تحویل:**
دیدم که حتی توی خودِ کانال منبع (تلگرام) هم فایل به‌صورت «1.1 MB
APPLICATION» عمومی نشون داده می‌شه — یعنی این مشکل از اول توی خودِ
فایل اصلیه، نه چیزی که ربات خراب کرده باشه. ربات فقط می‌تونه چیزی که
گرفته رو حفظ کنه، نه پسوند واقعی رو حدس بزنه. با این حال:
- کپشن پیام تحویل فایل الان **فقط شمارهٔ مود** هست (مثلاً `#9`)، نه چیز دیگه.
- اسم فایلِ تحویلی الان `<شماره>.<پسوند اصلی>` هست (مثلاً `9.apk`) — اگه
  پسوند اصلی رو نتونیم پیدا کنیم (چون خودِ فایل نداشتش)، بدون پسوند
  فرستاده می‌شه؛ چیزی نداریم که حدس بزنیم.
- یک خط دیباگ جدید هم اضافه شد که کل اطلاعات خامِ فایل رو لاگ می‌کنه
  (`file_info خام کامل: ...`) — بعد از تست بعدی، این خط رو از Actions
  برام بفرست تا مطمئن بشیم آیا روبیکا اصلاً اسم فایل رو با یک اسم دیگه
  (نه `file_name`) می‌فرسته یا نه.

**۳. دربارهٔ پیشنهاد backtick (\`\`) به‌جای quote ("") در state.json:**
این کار رو **عمداً انجام ندادم** چون یک باگ واقعی می‌سازه: JSON اصلاً
از backtick پشتیبانی نمی‌کنه (فقط `"..."` رشتهٔ معتبره) — اگه اینو عوض
کنم، خودِ فایل state.json دیگه JSON معتبر نیست و کل ربات کرش می‌کنه.
خبر خوب: نیازی به این کار نیست. `json.dump(..., ensure_ascii=False)`
که همین الان استفاده می‌کنیم، خودش خودکار خط‌های جدید (`\n`) و
کوتیشن‌های داخل متن (`\"`) رو escape می‌کنه — یعنی توضیحات چندخطی یا
دارای کوتیشن از قبل هم بدون باگ ذخیره می‌شه. نگران این بخش نباش.

**۴. سرعت پاسخ‌گویی:**
سرعت پاسخ کاملاً به فاصلهٔ اجرای ورک‌فلو بستگی داره. کرون داخلی گیت‌هاب
(`*/15 * * * *`) خودش تضمینی نیست و گاهی چند دقیقه دیر اجرا می‌شه (محدودیت
خودِ GitHub Actions). اگه زنگ‌زن بیرونی (cron-job.org) داری، سرعتش رو
می‌تونی با کم کردن فاصلهٔ زنگ زدن (مثلاً هر ۲-۳ دقیقه به‌جای ۱۵ دقیقه)
واقعاً زیاد کنی — این دقیق‌تر و سریع‌تر از کرون خودِ گیت‌هابه. فقط
توجه: هر اجرا حدود ۱۰-۳۰ ثانیه فقط برای بالا آمدن runner گیت‌هاب طول
می‌کشه؛ این حداقل تأخیریه که با این معماری (بدون سرور همیشه‌روشن) قابل
حذف نیست.

**۵. سقف برای سنگین نشدن:** لیست مودها و ویدیوهای ذخیره‌شده الان
حداکثر ۸۰۰ تای آخر رو نگه می‌داره (قدیمی‌ترها خودکار حذف می‌شن — فایل
واقعی که جایی گم نمی‌شه، فقط ارجاع داخلیش از آرشیو پاک می‌شه). لیست
خطاها (۲۰۰ تا)، `processed_updates` (۱۰۰۰ تا)، `sent_log` (۱ ساعت)، و
`recent_files` (۲ ساعت) از قبل هم سقف داشتن.

## 📋 راهنمای کامل دستورها و قابلیت‌ها

### دستورهای همگانی (هر کسی که به ربات پیام بده)
| دستور | کاری که می‌کنه |
|---|---|
| `/myid` | GUID (کد چت) خودش رو می‌فرسته |
| `/start` | اگه کانال اجباری تنظیم شده، لیستشون رو نشون می‌ده؛ وگرنه متن راهنما |
| `/help` | متن راهنما |
| `/ticket` | شروع تیکت — پیام بعدیش عیناً + GUID خودش برای تو (مالک) فوروارد می‌شه |
| شمارهٔ مود (`9` یا `#9` یا `/9`) | درخواست فایل مود شماره ۹ رو ثبت می‌کنه و لیست کانال‌های اجباری + راهنمای `/file` رو نشون می‌ده |
| `/file` | فایلِ **آخرین شماره‌ای که درخواست داده** رو می‌فرسته — **حتی اگه عضو کانال‌های اجباری نشده باشه** (طبق خواستهٔ خودت، این چک صرفاً اطلاع‌رسانیه نه قفل واقعی). هر درخواست فایل یک‌بارمصرفه؛ برای فایل بعدی باید دوباره شماره رو بفرسته و بعد `/file` رو بزنه. |

### دستورهای مخصوص تو (owner_guid)
| دستور | کاری که می‌کنه |
|---|---|
| هر متن دیگه | گزارش وضعیت کلی (تعداد کاربر/مود/ویدیو/باگ) |
| `پنل` (یا هر چی در `panel_keyword` گذاشتی) | لیست کانال‌های مقصد؛ بعدش عدد بفرست برای جزئیات همون کانال |
| رمز پخش همگانی (`broadcast_secret`) | پیام بعدیت برای همهٔ کاربرهای شناخته‌شده (پیوی) فرستاده می‌شه |
| `/channelcast` | پیام بعدیت توی همهٔ کانال‌های فعال پست می‌شه |
| `/postmod <شماره‌کانال|all>` | فوری یک مود تصادفیِ تکراری‌نشده به همون کانال(ها) پست می‌کنه، بدون توجه به ساعت |
| `/postvideo <شماره‌کانال|all>` | مثل بالا، برای ویدیو |
| `/post <شماره‌کانال|all>` | مثل `/postmod` |
| `/block <chat_id> <روز یا permanent> <دلیل>` | اون کاربر رو مسدود می‌کنه (پیام‌هاش دیگه پردازش نمی‌شه) |
| `/unblock <chat_id>` | رفع مسدودیت |
| `/blocked` | لیست کاربرهای مسدود |
| `/update` | از اول بافر روبیکا همه‌چیز رو دوباره می‌خونه — برای وقتی مشکوکی یه پست قدیمی از کانال منبع جا مونده |
| `/bugs` | گزارش خطاهای ثبت‌شده (صفحه‌به‌صفحه، هر بار ۵ تا) |

### رفتار خودکار
- **کانال منبع:** عکس با کپشن حاوی `#مود` (خط اول=عنوان، بعدش توضیحات
  — می‌تونه چند خط باشه، خودکار تا قبل از خط ورژن تشخیص داده می‌شه —
  بعدش ورژن، مثل `1.21` یا `ورژن: 1.21`) + فایلِ بعدی با همون شمارهٔ
  هشتگ = یک «مود» کامل. ویدیو با `#ویدئو`/`#ویدیو` = یک «ویدیو».
- **زمان‌بندی:** طبق `schedule.start_hour_tehran`/`end_hour_tehran` و
  پلن هر کانال (۰/۱/۲ یا بازهٔ اختصاصی)، خودکار مود/ویدیوی تصادفیِ
  تکراری‌نشده پست می‌کنه.
- **تشخیص اسپم:** بیش از ۱۵ پیام در ۵ دقیقه از یک نفر → به تو گزارش
  می‌ده (با GUID دقیق، حداکثر هر ۳۰ دقیقه یک‌بار برای همون فرد).
- **جلوگیری از سیل:** درخواست تکراریِ همون شماره از همون فرد ظرف ۱۰
  دقیقه نادیده گرفته می‌شه.

**۱. باگ «می‌گه فرستاد ولی توی کانال نیست» — رفع شد.**
`send_file` قبلاً هر پاسخ روبیکا (حتی بدون `message_id` واقعی) رو موفقیت
حساب می‌کرد. الان با ۳ لایه کار می‌کنه: مستقیم → اگه `message_id`
نداشت یا خطا داد، دانلود+آپلود مجدد فایل → اگه بازم شکست خورد، مستقیم از
کانال منبع **فوروارد** می‌کنه (تحویل تضمین‌شده‌تر، فقط متن سفارشی از
دست می‌ره). اگه بازم شکست خورد، حالا در `/bugs` می‌بینیش، نه سکوت.

**۲. باگ «تکرار پیام‌ها» (ریشه‌ای، مثل نسخه‌ی قبلی‌تون) — رفع شد.**
وقتی روبیکا `next_offset_id` خالی برمی‌گردوند (چون صفحهٔ آخر بود)،
`last_offset_id` هیچ‌وقت جلو نمی‌رفت و همون پیام‌های قدیمی هر اجرا
دوباره پردازش می‌شدن. الان در این حالت از شناسهٔ خودِ آخرین پیام
به‌عنوان offset بعدی استفاده می‌شه (در هر ۳ جایی که این الگو تکرار شده
بود: حلقهٔ اصلی، `/update`، و پاک‌سازی انبار).

**۳. جلوگیری از ارسال تکراری:** اگه یک کاربر همون شماره رو ظرف ۱۰ دقیقه
چند بار بفرسته، فقط بار اول واقعاً فایل ارسال می‌شه؛ بقیه بی‌صدا رد
می‌شن (بدون باگ اضافه، بدون پیام تکراری).

**۴. تشخیص اسپم:** اگه یک نفر بیش از ۱۵ پیام/کامند در ۵ دقیقه بفرسته،
یک گزارش به پیوی خودت می‌ره — شامل **GUID دقیق همون فرد** (هر ۳۰ دقیقه
حداکثر یک‌بار برای همون فرد، که خودت هم سیل نشی).

**۵. تیکت‌ها:** از قبل هم GUID فرستنده رو می‌فرستاد (خط «از: ...») — فقط
واضح‌ترش کردم («GUID فرستنده: ...»).

**۶. پلن‌های زمان‌بندی + بازهٔ کاری ۹ صبح تا ۱۱ شب:** در `config.json`
بخش `schedule` سه پلن آماده‌ست (۰ = هر ۲ ساعت مود/هر ۴٫۵ ساعت ویدیو،
۱ = هر ۱ ساعت/هر ۳ ساعت، ۲ = هر نیم‌ساعت/هر ۲ ساعت)، و هر کانال مقصد با
`"plan": 0` یا `1` یا `2` انتخاب می‌کنه، یا با `mod_interval_hours` /
`video_interval_hours` اختصاصی override می‌کنه. یک `schedule: cron` هر
۱۵ دقیقه هم به ورک‌فلو اضافه شد تا حتی بدون زنگ‌زن بیرونی (cron-job.org)
هم خودش کار کنه.

**۷. عضویت اجباری — ⚠️ با یک محدودیت واقعیِ پلتفرم که باید بدونی:**
سند رسمی متدهایی که خودت فرستادی رو کامل خوندم — روبیکا **هیچ متد
رسمی مستندی برای چک عضویت یک کاربر خاص در یک کانال نداره** (برخلاف
تلگرام که `getChatMember` داره). با این حال، چون متدهای `banChatMember`/
`unbanChatMember` دقیقاً با `chat_id`+`user_id` کار می‌کنن، به نظرم
منطقیه که یک متد خواهر برای «خوندن» وضعیت هم وجود داشته باشه، فقط در
این سند نیومده. بر همون الگو، `getChatMember` رو با `chat_id`+`user_id`
پیاده‌سازی کردم:
- اگه واقعاً وجود داشته باشه و جواب بده → عضویت واقعاً و دقیق چک می‌شه.
- اگه روبیکا بگه این متد وجود نداره → به‌جای گیر انداختن همهٔ کاربرهای
  واقعی پشت یه چکِ خراب، **fail-open** می‌کنه (رد می‌شن) و یک هشدار در
  `/bugs` ثبت می‌شه که بدونی باید دستی چک کنی.
**بعد از اولین تست /start، لاگ Actions رو باز کن و دنبال خط
`DEBUG: getChatMember خام:` بگرد و برام بفرست — دقیقاً همون الگویی که
دفعهٔ قبل با ساختار پیام‌ها جواب داد.**

**تنظیمات لازم قبل از تست:**
- `config.json` → `required_join_channels`: برای هر کانال اجباری،
  `guid` (با فوروارد یه پیام از اون کانال به بات، یا /myid داخل خودِ
  کانال) و `link` رو پر کن.
- بات باید **ادمین** همون کانال‌های اجباری هم باشه (نه فقط کانال‌های
  مقصد و منبع).

## ⚠️ فقط این‌ها رو جایگزین کنید (نه state.json!)
`bot_core.py`, `run_bot.py`, و در صورت نیاز `config.json`. **هرگز state.json
رو از این پکیج جایگزین نکنید** اگه قبلاً روی ریپوتون داده‌های واقعی (مود،
کاربر، ...) جمع شده — فیلدهای جدید خودشون در کد با مقدار پیش‌فرض ساخته
می‌شن، نیازی به جایگزینی state.json نیست.

## رفع باگ اصلی این نسخه
تشخیص «عکس مود» دیگه به رشتهٔ دقیق `file_type == "Image"` وابسته نیست
(چون معلوم شد این فرض همیشه درست نبود) — حالا **بر اساس تگ متن** (`#مود`)
تشخیص داده می‌شه، دقیقاً مثل فایل. این باگی که عکس‌ها ثبت نمی‌شدن رو رفع می‌کنه.

## قابلیت‌های جدید

### ۱. دکمهٔ ثابت `/help` و `/ticket`
هم برای کاربرهای جدید، هم برای خودِ مالک (بار اولی که پیام بده)، خودکار
یه کیبورد ثابت با دو دکمهٔ `/help` و `/ticket` پایین صفحه ظاهر می‌شه.

### ۲. سیستم تیکت
هر کاربری (نه فقط مالک) می‌تونه `/ticket` بفرسته → ربات می‌گه متنتو
بنویس → بعد از نوشتن، متن تیکت (با آیدی فرستنده و زمان) به پیوی شما
می‌رسه، و به کاربر «تیکت شما ارسال شد» گفته می‌شه.

### ۳. مسدودسازی کاربران (فقط مالک)
```
/block <chat_id> <تعداد روز یا permanent> <دلیل>
مثال: /block u0Iabc123 7 اسپم می‌فرسته
مثال دائمی: /block u0Iabc123 permanent مزاحمت

/unblock <chat_id>
/blocked   -> لیست کامل مسدودها با تاریخ شروع/پایان
```
کاربر مسدود، هر پیامی بفرسته فقط دلیل و تاریخ مسدودیتش رو می‌بینه؛ بعد
از پایان مهلت، خودکار آزاد می‌شه.

### ۴. پخش پیام در همهٔ کانال‌ها (نه کاربرها)
```
/channelcast
```
می‌گه پیامتو بفرست؛ پیام بعدی رو مستقیم در همهٔ کانال‌های **فعال** پست
می‌کنه. (این جدا از رمز پخش‌همگانیِ قبلی‌ه که برای *کاربرها*ست، نه کانال‌ها.)

### ۵. پست فوری، جدا برای مود و ویدیو
```
/postmod <شماره کانال یا all>     مثلاً: /postmod all یا /postmod 2
/postvideo <شماره کانال یا all>   مثلاً: /postvideo all یا /postvideo 1
```
بدون توجه به ساعت برنامه، همون لحظه پست می‌کنه.

### ۶. عضویت اجباری در کانال — با یه محدودیت صادقانه
مستندات رسمی روبیکا **هیچ متدی برای چک‌کردن عضویت کاربر در کانال نداره**؛
پس نمی‌تونم یه قابلیت واقعی و قابل‌اعتماد براش بسازم بدون این‌که دروغ
بگم کار می‌کنه. اگه دوست دارید، می‌تونم یه نسخهٔ «افتخاری» بسازم (نمایش
لینک‌های کانال‌ها + دکمهٔ «عضو شدم» که فقط حرف کاربر رو باور می‌کنه، نه
چک واقعی) — بگید تا اضافه‌ش کنم.

### حذف‌شده: `/newguid`
چون کار نمی‌کرد (به فیلد نامستندی وابسته بود)، کامل حذفش کردم. برای
گرفتن GUID هر چتی، همیشه مطمئن‌ترین راه همینه: مستقیم داخل همون چت/کانال
بنویسید `/myid`.

## 🛠 اصلاحات نسخه فعلی

- تأخیر طولانی ارسال فایل کم شده: در صورت شکست `sendFile`، اگر پیام از کانال منبع باشد ابتدا `forwardMessage` امتحان می‌شود و فقط در آخر `re-upload`.
- نوع‌های ناشناخته فایل مثل `Application` به `File` تبدیل می‌شوند تا فایل مود به شکل فایل معمولی نمایش داده شود.
- توضیحات مود چندخطی حفظ می‌شود و در کپشن کانال به همان صورت با خط‌های جدا قرار می‌گیرد.
- دریافت مود اکنون این روند را دارد:
  1. کاربر شماره مود را می‌فرستد؛
  2. ربات GUID کانال‌های موردنظر را نشان می‌دهد؛
  3. پایین پیام می‌گوید `/file` را بزنید؛
  4. با `/file` همان مود درخواست‌شده تحویل داده می‌شود، حتی اگر کاربر عضو کانال‌ها نشده باشد؛
  5. درخواست تحویل یک‌بارمصرف است و برای مود بعدی باید دوباره شماره مود ارسال شود.
- آپدیت‌های تکراری با شناسه update/message نیز dedupe می‌شوند.
- در `getUpdates` فقط `next_offset_id` معتبر API به‌عنوان offset ذخیره می‌شود؛ `message_id` دیگر به‌صورت حدسی جای offset استفاده نمی‌شود.
- مرحله ذخیره `state.json` در GitHub Actions timeout دارد و pull/push بدون ورودی تعاملی انجام می‌شود تا workflow روی آن مرحله چند دقیقه گیر نکند.

### فایل‌هایی که تغییر کرده‌اند

`bot_core.py`، `run_bot.py`، `.github/workflows/rubika-bot.yml`، `state.json` نمونه و `README.md`.

**state.json واقعی ریپوی خودت را با نمونه این ZIP جایگزین نکن** اگر داده‌های واقعی مود/کاربر داخلش داری. کد فیلدهای جدید را خودش می‌سازد.
